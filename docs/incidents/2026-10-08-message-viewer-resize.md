# 작은 창에서 메시지 그리드/뷰어 경계선이 튀는 문제

- 날짜: 2026-10-08
- 상태: 로컬 수정 및 검증 완료, 미배포
- 대상: Consume 메시지 그리드와 Message Viewer 사이의 세로 크기 조절
- 기준: `main`의 `52a8b358c727151242c13415314c6213f1745e56` 이후 작업 트리

## 증상과 원인

실제 `ConsumePanel`을 사용하는 로컬 샘플 화면에서 재현했다. 화면 크기 1100×720, 그리드와 뷰어를 합친 영역 높이 368.875px에서 경계선을 아래로 10px 끌면 그리드 높이가 230px에서 150px로 줄었다.

초기 표시는 저장된 높이를 그대로 사용했지만 드래그는 `Math.max(150, gridHeight - 250)`으로 상한을 계산했다. 두 기준이 달라 첫 이동에서 위치가 튀었다. 창을 줄일 때 높이를 다시 제한하지 않았고, 드래그 시작점도 실제 표시 높이가 아닌 저장값이었다.

좁은 분할 화면에서는 뷰어 도구 모음이 여러 줄이 된다. 뷰어 최소 높이를 고정값으로만 계산하면 도구 모음 아래 메시지 본문 공간이 부족해지는 것도 확인했다.

## 수정

- 표시, 드래그, 취소 복원에 같은 높이 계산을 적용한다.
- 드래그는 현재 보이는 그리드 높이에서 시작한다.
- 컨테이너와 도구 모음 크기를 관찰해 두 영역을 가용 공간 안에 배치한다. 도구 모음 높이와 메시지 본문 공간을 함께 고려한다.
- 창 축소로 일시적으로 제한한 높이는 저장하지 않는다. 다시 넓히면 선호 높이가 복원된다. 사용자가 직접 경계선을 움직인 경우에만 높이를 저장한다.
- 포인터 취소·캡처 상실·컴포넌트 해제 시 예약된 화면 갱신과 이벤트를 정리하고 기존 커서·텍스트 선택 스타일을 복원한다.

## 검증

- `npm test`: 34개 통과. 높이 범위, 10px 이동, 창 크기 변경과 저장값 보존, 취소·캡처 상실·언마운트, 다른 포인터 무시를 포함한다.
- `npm run build`: Renderer 타입 검사, Electron 컴파일, Vite 빌드 통과. 기존 번들 크기 경고는 남아 있다.
- 실제 `ConsumePanel`과 샘플 메시지를 사용하는 Edge 브라우저 검증에서 같은 10px 이동이 230→240px로 동작했다.
- 창 확대·축소, 뷰어 접기·펼치기, 좌우 pane 독립 조절, 취소·언마운트 정리를 확인했다.
- 800×660의 좁은 분할 화면에서 각 컨테이너 216.25px, 그리드 71.25px, 뷰어 137px로 경계 안에 배치되고 두 줄 도구 모음 아래 본문이 보였다.
- 독립 코드 리뷰에서 수정 범위의 추가 결함이 발견되지 않았다.

브라우저 검증은 로컬 샘플 데이터로 수행했다. 실제 Kafka 조회·발행은 이 검증에 포함하지 않았다. 극단적으로 작은 영역에서는 표시 가능한 행 수가 제한된다.
